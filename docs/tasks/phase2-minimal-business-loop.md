# 系统开发下一步实施计划

> 本文件是项目实施交接计划，不是毕业设计任务书。毕业设计任务书描述整个 C 语言考试系统的目标、功能、评测、测试和进度；本文件只拆解当前环境收尾后的第一批开发工作。

日期：2026-11-23

## 前置条件

第一阶段的首次空卷启动、Unity 版本发现、目标 SDK 选择和 MySQL 持久化已在 B 机完成 [合并前验收](../validation/2026-11-28-B-merge-acceptance.md)。

当前状态：已有演示账号、题库、组卷、考试会话、答案保存和客观题交卷评分接口。B 机已在指定提交通过 Unity 真实 API 的登录、答题、断线恢复和考试收尾；正式身份与邮件仍在后续范围。

## 目标

完成最小纵向闭环：用户注册/登录 → 服务端识别角色 → 获取题目 → Unity 展示单选题。所有核心数据仍由 ASP.NET Core 和 MySQL 保存，Unity 不直接连接数据库。

## 本批开发范围

1. 使用成熟 ASP.NET Core 身份框架处理账号、密码哈希、登录会话和角色授权。
2. 建立版本化数据库迁移：用户、角色、题目、知识点及最小题库种子数据；保留学号前导零的字符串语义。
3. 提供本地开发邮件替身，仅用于注册/验证流程联调；不接入真实供应商，不提交 API Key。
4. 实现学生登录后获取已发布单选题列表和题目详情；服务端过滤可见题库，客户端只接收允许展示的数据。
5. Unity 增加登录状态、错误提示、题目列表/详情和单选答案提交的最小界面；先完成 Windows SampleScene 演示。
6. 增加 API 集成检查：注册、登录成功/失败、过期会话、学生访问教师接口被拒绝、题目查询和重复请求。
7. 增加教师建题/组卷、学生开考、答案保存、重复交卷和客观题评分检查。
8. 增加题目可见性、考试学生分配和 Excel 兼容 CSV 导入；公开练习接口不得返回教师私有题。
9. 增加班级、学生成员、考试时间窗口和学生成绩查询，服务器统一执行截止时间。

## 当前仍不纳入

## 验收标准

- 从空数据库执行迁移和种子后，API 可启动并返回健康状态。
- 学生可以注册/登录并获取一组单选题；错误密码和过期会话被拒绝。
- 学生令牌调用教师接口返回 403，客户端选择教师角色不会改变服务端权限。
- 题目查询只返回已发布且当前用户可见内容；标准答案不随题目查询返回。
- Unity 在 SampleScene 中完成登录、题目展示和单选答案提交，失败时显示可理解的错误。
- A/B 使用各自数据库按同一迁移和种子重建；验证记录写明提交号、环境和实际响应。

## 实施顺序

先定迁移和 API 契约，再实现身份与题库查询，随后接 Unity 登录和单选界面，最后做权限/异常集成检查。每一步保持小提交并更新决定、实施、问题和验收记录；B 复验未通过前不进入正式考试流程。
