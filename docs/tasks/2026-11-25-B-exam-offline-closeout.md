# B 机考试收尾验收任务

## 目标

B 机使用 A 机交付的同一 Git 提交、同一数据库结构迁移和同一脱敏测试数据，独立验证到期自动交卷、断网重启、截止前补传和截止后只读状态。

## 环境

1. 拉取 A 机给出的提交号，确认工作区没有未提交内容。
2. 按 `.env.example` 创建 B 机自己的 `.env`，使用 B 机独立的随机密码和未占用回环端口。
3. 执行 `tools/check-environment.ps1`，再执行 `tools/start-local.ps1`。
4. 使用 Unity 2022.3.62f3c1 打开 `client/`，运行 `Assets/Scenes/SampleScene.unity`。

数据库使用 B 机自己的 Docker volume。通过代码中的结构迁移和演示种子建立数据，保留 A 机测试账号和题目语义。不要复制 A 机数据库 volume、`.env` 或真实答卷。

## 验收步骤

1. 创建一场 4 秒后截止的单选考试。学生开考后退出 PlayMode，等待超过截止时间，教师刷新答卷列表。预期答卷显示 `Submitted`，总分采用截止前已经确认保存的答案。
2. 创建一场有足够剩余时间的考试。学生选中两题，确认至少一题显示自动保存，停止 API 或断开网络，退出并重新启动 Unity。恢复 API 或网络且仍未截止时进入同一答卷，预期本地选项回显并按退避策略补传。
3. 创建另一场短考试。学生选题后在截止前断网，等待超过截止时间，再恢复 API 或网络。预期客户端只查询答卷状态，服务端拒绝截止后的答案写入，教师看到截止前已保存的答案。
4. 修改客户端本地草稿中的旧 revision，恢复网络后验证服务器较新答案不会被覆盖。
5. 记录机器、提交号、Unity/.NET/Docker/MySQL 版本、操作、响应和截图，写入 `docs/validation/YYYY-MM-DD-B-exam-offline-closeout.md`。

## 通过标准

- 到期答卷能进入教师批阅列表。
- 截止前恢复能补传待同步答案，重复请求不覆盖新 revision。
- 截止后恢复不上传逾期答案，学生端能看到状态同步结果。
- A、B 使用独立数据库，代码提交、迁移版本和验收记录一致。
