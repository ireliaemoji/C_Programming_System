## 实施顺序

### 1. 调整 Docker MySQL 和配置

- 检查当前 Compose、API 连接配置、原生实例和已存在的卷，确认端口占用归属。
- 将 MySQL 宿主机端口限制到回环地址，不发布 33060；保持 API 只监听 localhost。
- 统一 A/B 的 MySQL 镜像版本并固定版本，优先与现有 8.4 系列一致；验证所选镜像可用且与连接器兼容，写入依据。不要把现有 8.4 数据目录直接挂给 8.0。
- 为本地凭据提供不含真实秘密的配置示例和明确的加载方法，实际随机密码保存在被 Git 忽略的文件或机密配置中。Compose 与 API 必须读取同一套本地配置，不能只改一端。
- 机密不得进入 Unity、Git、命令输出或日志。修改 `.gitignore` 时只忽略实际机密/备份路径，不忽略需要版本控制的结构迁移和示例文件。
- 已存在卷的密码不能靠重写环境变量假定已更新。遇到既有数据/凭据不匹配，保留数据并说明处理路径，不删除卷来重建。
- 需要停止原生 MySQL 时，先确认是本项目实例，安全关闭；不杀死所有 mysqld 进程、不卸载、不删数据。优先明确解决端口冲突，不增加无必要的多种数据库后端。

### 2. 修正环境检查/安装工具

复用 `tools/check-environment.ps1`，支持两台电脑的相同环境流程：

- 默认只读检查：实际 Unity 编辑器及版本、项目需要的 .NET SDK、Docker CLI、Compose、引擎连接能力和项目 MySQL 容器状态。
- Unity 版本文件存在不能代表 Unity 已安装；找到任意 dotnet 命令不能代表目标 SDK 可用；Docker Desktop 状态文字不能代替引擎连接检查。
- 显式安装选项只安装缺失且必需的组件，默认不再安装原生 MySQL；Unity 通过 Hub/授权或管理员操作无法自动完成时，准确列出人工项。
- 区分“未安装”“安装但未运行”“重启待完成”“端口冲突”和“数据库未就绪”。检查实际退出码，安装失败不能打印成功；缺少前提时给出非零退出状态。
- 外部命令与数据库启动等待需要合理超时，不能无限等待或固定睡几秒就宣告成功。
- 不自动重启 Windows、不改防火墙/公网端口、不绕过权限、不强制关闭 Unity。
- 旧 `-StartMySql` 要么明确改为容器语义并同步文档，要么用清楚的新参数替代，不能继续静默启动空密码 root 的原生实例。

### 3. 提供最小本地启动流程

- 在现有工具或一个简短启动脚本中实现：加载本机配置 → 检查 Docker → 启动本项目 MySQL 容器 → 等待数据库认证查询成功 → 在 localhost 启动 API。
- 显示启动失败所在环节，保留必要进程供 Unity 联调；正常停止 API 不应删除数据库卷。
- 处理 API 已运行和端口被其他进程占用的情况，不自动终止不明进程。
- 保持 `/health` 成功返回 200 和 `database: ok`，失败返回 503；移除对客户端直接返回的内部异常详情，服务端诊断也不能包含秘密。
- README 写出唯一推荐启动流程、停止方法、重复执行行为以及需要人工完成的事项。

### 4. 留下可复验的检查与记录

- 为脚本的关键成功/失败行为保留一个最小可执行检查，重点验证失败不会误报成功；不必引入额外测试框架。
- A 做本机验收，记录软件版本、提交号和实际命令结果；B 用相同提交独立复验。
- 可按 [验收记录模板](../validation/template.md) 记录。问题继续纳入 `docs/issues-and-solutions.md`，阶段状态同步到 README 和 `docs/phase1-implementation.md`。

## 验收标准

| 验收项 | 要求 |
|---|---|
| 环境检查 | 组件缺失或引擎不可用时明确失败，并指出人工动作；不误报 READY |
| 可重建 | 从干净的项目专用 Docker 环境和本机私密配置可初始化，不依赖 A 原生数据库 |
| 重复执行 | 再次启动不覆盖既有数据/凭据、不重复启动冲突的 API |
| 数据库 | 容器内应用账号认证并执行查询成功；记录实际镜像版本 |
| 后端 | 编译通过，运行后 `/health` 返回 200 |
| Unity | `SampleScene` 实际请求成功，提供脱敏日志；若 Unity 被占用或未安装，标为待人工验证 |
| 失败行为 | 数据库不可用时返回 503，响应不泄露内部异常或秘密 |
| 持久化 | 在隔离的临时测试记录上验证容器重启后数据保留；不删除既有业务表或卷 |
| 网络与秘密 | API/MySQL 仅本机可访问，不开放 33060；秘密与真实数据未进入 Git |
| B 验收 | B 独立启动并记录对应提交号；没有 B 的实际证据就保持待验收 |

A 完成代码并不等于 B 验收已完成。B 暂不可用时，完成可验证部分并明确交接剩余步骤，不编造测试结果。
