# 两台电脑的开发、验收与数据管理

更新日期：2026-11-19
状态：用户已确认当前采用 A 开发、B 独立验收；本轮已将 Docker 默认流程和环境工具按此方案实施，A/B 实际运行验收仍分别进行。

## 当前采用的方案

本机 A 同时开发 Unity 客户端和 ASP.NET Core 服务端，并使用自己的 Docker MySQL 开发库。另一台电脑 B 拉取指定 Git 提交，运行自己的客户端、API 和 Docker MySQL 测试库，验证并记录问题，再交回 A 修复。

不按电脑拆分客户端/服务端开发职责，也不把 B 的数据库作为 A 的开发主库。B 的测试环境不依赖 A 在线。

```text
电脑 A：Unity → 本机 API → Docker MySQL → A 的 volume
                开发、修复、提交代码
                         ↓ Git 指定提交
电脑 B：Unity → 本机 API → Docker MySQL → B 的 volume
                验收、复现、记录问题
                         ↓ Git 问题记录
电脑 A：修复并提交 → B 复验
```

| 内容 | A：开发机 | B：验收机 |
|---|---|---|
| 代码 | 实施功能和修复 | 拉取指定提交，保留复现现场 |
| 数据库 | 独立开发库 | 独立测试库 |
| 数据 | 无敏感信息的开发数据 | 固定测试案例和测试数据 |
| 主要交付 | 提交号、运行说明、结构迁移、种子数据 | 提交号、测试结果、复现步骤和脱敏日志 |

本机当前仍可能运行原生 MySQL，历史上曾验证 Unity/API/MySQL 闭环成功；本轮未停止或覆盖它。Docker 流程现在固定使用 MySQL 8.4.9、回环端口和未提交的 `.env`。A 的 Docker/Unity 实际运行结果与 B 的系统和实际运行结果仍需现场记录。

## 数据如何保持一致

Docker 账号不保存或自动同步本机数据库 volume。两台电脑登录同一账号、使用相同 Compose 文件或卷名，仍然各有一份数据库。

- Git 同步代码、环境定义、数据库结构迁移和无敏感信息的种子数据。
- 两边使用相同 MySQL 版本、相同迁移版本和相同种子数据版本，建立可比较的测试环境。
- 当前只有健康检查，没有业务表；本轮无需为将来的业务预先创建表。后续增加业务表时，再提交对应的迁移与种子数据。
- 不要求复制全部数据。只有问题依赖特殊记录时，才传递经过脱敏的测试案例或逻辑备份。
- 真实数据、密码、数据库原始目录、备份不提交 Git。数据库备份放在 volume 外，并保留受控的加密副本。
- Named volume 提供持久化，不等于备份；不要执行 `docker compose down -v`、重置 Docker 或同步运行中的数据库目录来“更新测试环境”。

## 每轮协作流程

1. A 实施功能并完成本机检查，提交代码、运行说明、迁移和必要测试数据，提供确切提交号。
2. B 检查自身 Git 工作区，保存未提交的验证记录后拉取该提交；不能直接覆盖或重置未提交内容。
3. B 按文档启动自己的环境，记录软件版本、结构/种子数据版本和实际测试结果。
4. B 按 [验收模板](validation/template.md) 新建记录。问题包含预期、实际、最小复现步骤和脱敏证据；未知原因标为待查，不当作事实。
5. B 将问题文档提交 Git；不得把密码、真实用户资料、整个数据库或整份未脱敏日志上传。确需代码修复时交回 A 实施。
6. A 修复并给出新的提交号，B 复验，在原问题中追加修复提交和结论。

## 网络与个人数据安全

当前 A、B 都使用本机 API，开发/验收不需要互开数据库或 API 端口，不需要路由器端口转发或远程数据库账号。Git 是代码和脱敏问题记录的交接通道。

- API 在各自电脑上监听回环地址；MySQL 在宿主机运行 API 时只发布到 `127.0.0.1`，API 容器化时可仅使用容器内部网络。
- 不发布 MySQL X Protocol 33060，不暴露 Docker 管理接口，不使用特权容器或挂载个人文件目录。
- 数据库应用账号不用 root；随机凭据仅保存在本机私密配置，示例凭据不能作为真实密码使用。
- 个人电脑所有权不等于绝对安全；本机恶意软件、账号被盗、误提交资料和错误端口配置仍可能泄露数据。
- 同步到 Git 的是有意共享的代码和脱敏记录，真实数据不随之共享。

## 保留为后续选项的共享部署

上一版“A 访问 B 的统一 API 和数据库”方案不再作为当前开发安排。以后需要集中演示、多人共享业务数据或正式部署时，再单独启用该方案。

届时再确定唯一数据源、迁移/回退流程、固定服务地址、身份认证、权限、HTTPS、网络访问限制和备份。不同网络可评估私有 VPN，但 VPN 不能代替业务授权。当前不执行跨电脑数据库迁移或共享网络配置。
